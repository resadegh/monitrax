## The withdrawal — worth recording in full

An earlier VR-047B returned **FAIL** with `failureClass: INSTRUMENT_UNREACHABLE` and recommended
shipping an auth change. **It was wrong, and it is withdrawn in full.**

The Matrix had switched from a page-context `fetch(url, {credentials:'include'})` to address-bar
navigation, and read the resulting `SESSION_INVALID` as an app defect. Reza refused the diagnosis —
*"you never had this issue in the past month — what has changed?"* — and reading the session transcript
rather than reasoning from memory settled it: **all 39 successful relay calls ever made used the
page-context fetch; not one used navigation.** The dates disprove the story built on top of it too —
GCP admin auth landed 2026-04-12, the relay was built 2026-07-29, so the cookie never existed for a
single day of the relay's life.

**No code change was needed and the recommended cookie change was not made.** Two things follow, both
acted on in the same PR as this record:

1. **MON-155** — `extractAdminToken` (`lib/admin/auth.ts:501`) really does read an `admin_session`
   cookie that nothing writes. That half-present branch is what made the wrong diagnosis plausible.
   Verified independently before registering: the only other reference on main is the logout clear.
2. **Every handout now says `fetch(url, {credentials:'include'})` from an authenticated admin tab**,
   not `GET <url>`. The old phrasing reads as "navigate here" and is unrunnable that way.
