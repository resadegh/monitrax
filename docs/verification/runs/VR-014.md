## Findings this run

1. **MON-087 (NEW, Sev-1, `changesNumbers: false`):** opening **Add Expense from a property detail page** (`/dashboard/properties/[id]` → PropertyExpensesCard → the canonical `components/ExpenseDialog`) throws the app error boundary: *"A `<Select.Item />` must have a value prop that is not an empty string."*
   - The **global** Add Expense (`/dashboard/expenses`, its own inline form) opens and works — MON-083 confirmed working there (untick recurring → "One-off — counted once, on the date it happens").
   - **Root cause (§19.2, verified in source):** the property context pre-selects `sourceType: 'PROPERTY'`, so the Linked-Property `<Select>` renders immediately — before the dialog's async `loadRelatedData()` fills `properties` — and the `properties.length === 0` branch rendered `<SelectItem value="" disabled>No properties available</SelectItem>`. Radix throws at render on any empty-string item value. Not MON-083's conditional (that logic never shipped to this dialog — see finding 2).
   - **Class sweep (clause 4 holistic):** the same empty-value `SelectItem` pattern existed at **15 sites** — `components/ExpenseDialog.tsx` ×4, `app/dashboard/expenses/page.tsx` ×4, `app/dashboard/income/page.tsx` ×3, `components/transactions/TransactionLinkDialog.tsx` ×5 (latent: crash whenever the relevant list is empty at render), plus 4 **functional** empty-value options (`audit-logs` "All Actions"/"All Statuses", income + investments-transactions "None").
2. **MON-083 gap on this entry point:** the canonical `ExpenseDialog` had **no `isRecurring` control at all** — a one-off could not be expressed from the property context (every save inherited the schema default `true`).

## Fix (Code session, same day — form-only PR)

- The 11 "No X available" placeholders → plain disabled `<div>` rows (not Select.Items). The 4 functional options → non-empty sentinels (`'ALL'` / `'NONE'`) mapped back to `''`/`null` in `onValueChange`; root `Select value` props moved off `|| ''` onto `?? undefined` (the Radix placeholder pattern). Zero empty-value items remain repo-wide.
- **MON-083 parity:** `ExpenseDialog` gains the recurring checkbox + conditional Frequency ("One-off — counted once, on the date it happens"), `isRecurring` in its form state/init/submit; `PropertyExpensesCard.toDialogExpense` threads `isRecurring` for edits. Same semantics as the expenses-page form; consumption is already gated by `monthlyRunRate()`.
- **Ratchet (promotion):** `tests/ui/selectItemEmptyValue.test.ts` — static source scan failing on ANY `<SelectItem value="">` in `app/` + `components/`. Chosen over a mounted-dialog smoke test deliberately: the repo has no react-mount harness, and the defect is fully static (an empty-value item in source IS the render crash), so the scan covers every entry point and every future instance of the class.
