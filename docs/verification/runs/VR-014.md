## Addendum — the MON-087 fix (Code session, PR #1446, same day)

**Root cause (§19.2, verified in source at the pre-fix anchors):** the property context pre-selects `sourceType: 'PROPERTY'` in the dialog's open-effect, so the Linked-Property Select renders BEFORE the async `loadRelatedData()` fills `properties` — and the empty-list branch rendered `<SelectItem value="" disabled>No properties available</SelectItem>` (`components/ExpenseDialog.tsx:515`, plus :544/:576/:608 siblings). Radix throws at render on any empty-string item value. The global page never crashed because it uses its own inline form.

**Class sweep (clause-4 holistic):** the same pattern existed at **15 sites** — ExpenseDialog ×4, expenses page ×4, income page ×3, TransactionLinkDialog ×5 latent, plus 4 functional empty-value options (audit-logs "All Actions"/"All Statuses", income + investments-transactions "None"). All fixed in #1446: placeholders → plain disabled `<div>` rows; functional options → `'ALL'`/`'NONE'` sentinels mapped back to `''`/`null`; root `Select value` props off `|| ''` onto `?? undefined`.

**MON-083 parity closed on this entry point:** the canonical ExpenseDialog had NO `isRecurring` control (a one-off was inexpressible from the property context). #1446 adds the recurring checkbox + conditional Frequency ("One-off — counted once, on the date it happens") + `isRecurring` in state/init/submit; `PropertyExpensesCard.toDialogExpense` threads it for edits.

**Ratchet (promotion):** `tests/ui/selectItemEmptyValue.test.ts` — static source scan failing CI on ANY empty-string SelectItem value in `app/` + `components/` (chosen over a mounted-dialog smoke test: no react-mount harness in the repo, and the defect is fully static, so the scan covers every entry point + future instances).

**Owed after #1446 merges:** Matrix re-check — Add Expense opens from the property page; one-off saved there persists `isRecurring=false`, counted once → **MON-087 + MON-083 → VERIFIED**.
