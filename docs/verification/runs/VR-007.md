## Headline result — a critical, previously-unknown tax defect (MON-053)

**One-off income is annualised ×12 into the tax base.** Two ATO deposits — `Ato Ato001100022493651` ($9,098) and `Ato Ato002000023189359` ($952) — are each a **single transaction dated 27 May**, stored as `Income{frequency: MONTHLY}`, and extrapolated to $109,176/yr and $11,424/yr. That is **≈$120,600 of phantom income** inside the declared gross of $524,831/yr — **and it is taxed**.

This is **MON-037's income-side twin**. MON-037 fixed the identical bug for *expenses*; income was never given the same treatment, so the pattern survived. Root cause is §19.2-verified in code (see MON-053 in the registry — 18 `file:line` anchors). **A one-off income is currently inexpressible in the data model:** `model Income` has no `isRecurring` column (`model Expense` does) and `enum Frequency` has no `ONE_OFF` member.

Storage corroborates 6 (2.2+2.9+2.8+2.1+2.0+2.0 = 14.0 MB == "STORAGE 14.0 MB used"). **The fix is to COUNT DOCUMENTS, not to add `tax:` to the exclusion list** — another prefix exclusion re-arms the bug the moment a fifth taxonomy appears. - **(G) The brief reports display rounding as a mismatch, every run.** All 6 Home-vs-detail deltas were exactly `round(detail/12)×12 − detail` (Las Vegas 0, Broadbeach −3, Thornland Lot 2 −4, Thornland Lot 1 0, HOME +4, Guildford −5) — **6/6, verified mechanically.** The Home tile renders a rounded MONTHLY figure; the brief's `×12` re-inflates it, then `crossSurface[].match` is a hard PASS/FAIL (§3.3 :187), so **4 false FAILs are reported every run**. **NOT fixed in this PR — deliberately.** The fix belongs in `VERIFICATION_PLAYBOOK.md` §3.3, but that file **moved under us**: our analysis pin carries blob `db870d8c` while live `main` carries `25cda592` (#1416 wired a "playbook §3.2 automated-mode note" into it). The VM clone cannot fetch (private repo, no credentials), and at 29.5 KB the file is too large to reproduce verbatim through a connector without risking a silent revert of #1416 — so the edit was **reverted rather than pushed on a stale base**. **Exact change for a git-capable session** (one edit, §3.3 Part A, after "State MATCH or MISMATCH by $X across the three."): _the Home tile renders a ROUNDED MONTHLY figure, so ×12-ing it re-inflates the rounding; judge the Home tile a MATCH when `homeMonthlyRendered === round(detail/12)`; keep reporting `cashflowYrHome` as that monthly ×12 so the baseline stays comparable; never raise a MON for a delta this rule explains; a delta it does NOT explain is a real FAIL._ Chosen over a tolerance band because a band would also hide *real* small deltas.

- **(I) NEW — `issues:raise` de-dup silently swallows distinct defects.** Its rule is *shared semanticKey **+** surface* (`raise-issue.mjs` `findDuplicate`).
