**Symptom (live):** On `/dashboard/balances` → "Where your wealth is", the caption under **Liquid today ($301,808)** reads the generic **"Reachable today — a typical buffer."** — NOT the cards-aware **"Reachable today, after your credit cards."** that the fix promised. So the $2,496 Balances-vs-Safety-Net difference remains unexplained to the user — the exact gap MON-031 was written to close.

**Not a stale deploy.** Production is `960e2ce8`, which includes #1368 (`b9a2db0f`, merged 2026-07-12). The deployed code has both caption branches (`components/balances/HiddenWealthLens.tsx:104/107`).

**Root-cause direction.** The cards-aware caption is guarded by `creditCards > 0` (`HiddenWealthLens.tsx:104`), fed by `breakdown?.creditCards` (`:151`). The API (`app/api/dashboard/hidden-wealth/route.ts`) *does* pass `breakdown.creditCards = b.creditCards`, and `computeAccessibilityBuckets` computes `liquidToday = liquidBasis − liabilities.creditCards`. Yet the guard evaluates false on Reza's data → the value reaching the component is ≤ 0. Most likely the $2,496 difference is actually produced by `liquidCash` being pre-netted (or `liabilities.creditCards` arriving as 0 for this NAB-card + Bankwest-offset setup) rather than by the `− creditCards` subtraction the caption keys off. **The guardrail copy exists but its trigger is not wired to the real driver of the gap** — a "looks-done-but-silently-inert" guardrail.

**Handoff (Code session):** trace `liabilities.creditCards` through `getMasterFinancialSnapshot` → `computeAccessibilityBuckets` for this account topology; trigger the cards-aware micro-copy off the actual driver of the Balances-vs-SafetyNet delta; add a Ring-2/Ring-3 assertion (fixture: user with a card balance → cards-aware caption renders).
