## Root cause (why the class surfaced)
Intake (manual add / transaction link / document import) stamps `frequency = MONTHLY, isRecurring = true` by default and never classifies a **single-deposit one-off**. A single bank credit (refund, rebate, casual booking) silently became "monthly recurring" → ×12 phantom in declared gross. The link gate only pre-ticked *recurring* at ≥2 matching payments; the single-transaction case fell through to the monthly default. This one blind spot is the whole MON-023 → MON-037 → MON-053 lineage.

## Guardrails
- **Shipped (#1421):** (a) intake now classifies a single imported transaction as one-off, not silent-monthly; (b) build-gate Ring-1 **source-lock** — every income/expense annualisation site must be one-off-guarded or the build fails.
- **Decision (Reza 2026-07-15): SOURCE-AWARE default** — declared/manual income & expense stay RECURRING; single-transaction imports default ONE-OFF. A blanket default-to-one-off was **rejected** (would under-count recurring bills/income and over-state disposable income).
- **New (MON-075):** standing NeoAudit detector — flag any recurring income/expense evidenced by a single $0-actuals transaction (the bug fingerprint) for review.

## Decisions & abandonments
