## What this says (honestly)

- **L0 structural completeness is now PROVABLE and gated:** 1,064 `.ts(x)` files on disk under `lib/`+`app/` → **1,062 represented + 3 allowlisted = 100%** (the gate fails the build on any uncovered file). The 3 allowlisted are verified graphify-0.8.45 limitations, none a financial calc — see `structural/coverage-allowlist.json`.
- **The meaning layer is a small, honest fraction of the whole.** The codebase has **8,587** structural symbols; the semantic Neomatrix models **64 engines**; calc-audit proves **93**. So *"is everything captured?"* now has two distinct, measured answers:
  - **Structurally: yes (100%, gated).** Every file and symbol is on the map.
  - **Semantically: partially**, and the gap is now **visible** — un-curated code is a delta against a complete L0, not silently absent.
- This is the denominator that was always missing. Coverage % from here on is `modelled ÷ this`, printed by the build — never a human claim (CLAUDE.md Part 22).

## How completeness is guaranteed (the mechanism, not a promise)

1. **L0 is extracted from code, not typed.** `graphify update lib app` parses 100% of files (tree-sitter); the run reports `540/540` + `528/528` (100%).
2. **An INDEPENDENT disk-vs-graph gate** (`scripts/neomatrix/check-layer0-coverage.mjs`, pure-node, in `neomatrix:check` → `vercel-build`) reconciles every on-disk `.ts(x)` against the committed graph. It **caught 3 real omissions** graphify's own "100%" missed (2 secret-name skips + 1 id-collision drop) — proving the gate works. A new uncovered file → red build.
3. **Regenerated + committed**, so the map can never silently lag the code (the failure mode that produced the recurring "gaps").
